# Подключение автозагрузки Авито Pro по постоянной ссылке — Иркутск

**Статус на 15.10.2026: НЕ ПОДКЛЮЧЕНО И НЕ ПУБЛИКУЕТСЯ.**

XML v3 для 4 тестовых товаров (2 рулевые рейки, 2 тормозных диска) проходит Avito XML-проверку без красных ошибок. 46 остальных артикулов ещё без документально подтверждённых OEM-кроссов и не должны попасть в фид. Данные по складу РОССКО — исключительно Иркутск, срок поставки 0, остаток >0. Цены = РОССКО +37% с округлением вверх до 50 рублей. Идентификаторы объявлений постоянные.

## Уже работает в ветке проекта

- `avito_sync_staging.py` получает **новый** прайс РОССКО и пересчитывает 4 SKU; не использует устаревший файл, сообщает об отсутствии товара.
- `avito_feed_transition.py` сравнивает две версии XML и блокирует пустую выгрузку, неожиданную массовую потерю ID и экстремальные скачки цен.
- `tests/test_avito_feed_transition.py` проверяет обновление цены, снятие одной отсутствующей позиции и возврат с тем же ID в следующем обновлении.
- `.github/workflows/avito_pilot_refresh.yml` готов к четырём проверкам за сутки: 07, 11, 15, 19 Иркутск (UTC+8; расписание в GitHub задано по UTC). Пока изменения **не в основной ветке**, расписание GitHub Actions **не будет** работать. Сейчас workflow создаёт только приватный временный review-артефакт и не публикует фид.
- Зарезервирована отдельная ветка `avito-irkutsk-feed` под постоянную XML-ссылку. В ней **не создан рабочий публичный XML**, и эту ветку ещё нельзя использовать как источник Авито.

## Задача продавца в Авито Pro

В разделе «Автозагрузка» нажать `Настройки` → `Перейти на загрузку по ссылке` и прислать **скриншот следующего экрана, не нажимая «Сохранить» и не включая публикацию**. Это позволит понять, какие настройки аккаунт применяет к текущим объявлениям и расписанию. Никаких дополнительных отчётов о старом XLSX отправлять не требуется.

## Перед включением живой связи

1. Проверить в кабинете, чем управляет текущая ручная загрузка, и не затронет ли переключение не связанные с нами объявления.
2. Протестировать снятие/возврат одного товара по отсутствию его `Id` в XML или по `DateEnd` (согласно правилам аккаунта), включая **ситуацию, когда все 4 SKU кончились**. Не оставлять прежний XML с некорректным обещанием наличия.
3. Включить собственный постоянный HTTPS-URL для пилота 4 SKU и GitHub Actions, публикующий **только после успешной проверки**. Права записи репозитория, принципы обращения с платными размещениями и способы немедленно остановить фид проверить отдельно.
4. Перенести настройки расписания в основную ветку GitHub только после проверки. Подтвердить, что Авито успешно загружает объявление по URL и что старые ID обновляются, а не дублируются.
5. Проверить сумму возможного списания за размещение/продвижение; включение источника может создать реальные объявления.

**Не публиковать сейчас URL скачивания ZIP артефакта GitHub Actions**: эти ссылки временные и Авито не сможет получать по ним регулярные обновления.
